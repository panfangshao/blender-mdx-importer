# 动画稳定性修复（1.1.2）

## 本次修复

- 导入完成后选中骨架和姿态骨骼，自动绑定第一个序列的 Action 与 Slot；没有序列时绑定静止姿态。
- 每个序列保存骨架 Action、网格对象和网格 Action 的直接引用，避免重复导入后 Stand、Walk 等同名动作串用，也支持对象和动作改名。
- 切换动画按属性所属骨架查找对象，不依赖当前活动对象；对无效列表下标安全退出。
- 播放范围使用 MDX 序列时长，而非最后一个关键帧的位置；切换时回到起始帧，并同步已开启的预览范围。
- 使用 MDX 节点 ID 映射枢轴、父子关系和顶点组，修复父节点 ID 为 0 被跳过，以及节点排列顺序不同导致的关联错误。
- 使用 Blender 实际骨骼名生成并转义动画路径，支持重复骨骼名、引号和反斜杠。
- 保留小数帧，不再把相邻关键帧四舍五入到同一整数帧；无轨道的变换分量也写入默认值。
- 场景帧率换算计入 fps_base；删除序列后修正列表下标。

## 安装与查看

安装当前目录的 `io_scene_warcraft_3_1.1.2.zip`，重启 Blender 后，在新场景重新导入 MDX。源码修改不会自动更新已经安装的插件副本；已经导入的数据也不会自动重新生成。

导入后骨架对象名通常为“模型名 Nodes”。在其数据属性的 WarCraft 3 / Animations 列表中切换序列。这里的骨骼是 Blender Armature / PoseBone，STICK 仅是显示方式，不是另一种不能编辑的骨骼系统。

如果动画在动但底部没有关键帧：

1. 选中骨架对象，而非模型网格。
2. 在姿态模式按 A 选中骨骼。
3. 在时间轴或摄影表的过滤选项中检查“仅显示选中项”；在摄影表中按 Home 查看全部关键帧。
4. 如果动作编辑器固定了其他数据，解除固定，并检查当前动作/槽位。优先使用插件序列列表切换，以同步网格颜色动画。

Blender 官方时间轴说明：https://docs.blender.org/manual/en/4.2/editors/timeline.html

## 删除日志

本插件源码没有调用物体删除操作，也没有在播放时删除对象的处理器。“operator | 已删除 1 个物体”不是本插件设计的动画步骤。仅凭两行日志无法判定是谁触发；如果只播放就出现该日志，需要结合当时的操作、其他插件和物体列表变化进一步定位。

## 验证范围与限制

已在本机 Blender 5.2.2 LTS 后台运行：

- `tests/blender_animation_regression.py`：节点 ID/父子关系、重复骨骼名、路径转义、Action Slot、重复导入、对象与动作改名、非骨架活动上下文、播放/预览范围、骨骼与颜色求值、无效下标、保存重开。
- `tests/blender_mdx_smoke.py`：生成经典版本 800 MDX，经过注册的导入操作器、二进制解析、网格/材质/骨架创建，检查动画顶点实际位移。

运行方式：`blender --background --factory-startup --python-exit-code 1 --python tests/blender_animation_regression.py`，另一测试同理。

测试使用合成模型，尚未获得用户出现异常的实际 MDX，也未做交互界面的视觉验证。此次不是完整 MDX 动画实现重写：原解析器仍丢弃全局序列 ID 和 Hermite/Bezier 切线，旋转仍采用欧拉曲线，这些可能影响特定模型的还原精度。旧 blend 文件只保存了序列名称，保留名称查找兼容，但无法可靠恢复旧文件中已混淆的同名动作；建议重新导入。
